# Code Review Standard (코드 리뷰 표준)

코드베이스의 지속 가능성, 버그 예방, 뛰어난 사용자 경험 및 가독성을 유지하기 위해 코드를 작성하거나 수정할 때 다음 기준을 필수적으로 점검합니다.

---

## 1. TypeScript 엄격성 및 타입 안전성 (Type Safety)
- **`any` 타입 전면 금지**:
  - `any` 대신 구체적인 `interface`나 `type`, 또는 타입 가드와 함께 `unknown`을 사용합니다.
- **명시적 컴포넌트 Props**:
  - 모든 컴포넌트의 Props는 명시적 인터페이스로 선언하고, 옵셔널 필드(`?`)에는 합리적인 기본값(Default values)을 할당합니다.
- **엄격한 Null/Undefined 가드**:
  - 역 정보(`Station`), 출구(`ExitInfo`), 추천 데이터 등 배열 탐색 시 `find` 결과가 `undefined`일 수 있음을 항상 전제하고 옵셔널 체이닝(`?.`) 또는 널 병합 연산자(`??`)로 방어합니다.

---

## 2. React 아키텍처 및 렌더링 성능 최적화
- **단일 책임 원칙 (SRP)**:
  - 하나의 컴포넌트는 한 가지 주요 역할(UI 프레젠테이션 또는 데이터 로직)에 집중합니다.
  - 지나치게 비대한 컴포넌트는 작은 재사용 가능 단위(컴포넌트/커스텀 훅)로 분리합니다.
- **불필요한 리렌더링 방지**:
  - 자주 리렌더링되는 부모 컴포넌트에서 무거운 자식으로 콜백 함수를 넘길 때는 `useCallback`을 적용합니다.
  - 대용량 데이터 계산(역 검색 필터링, 정렬 등)은 `useMemo`로 메모이제이션합니다.
- **코드 스플리팅 (Code Splitting)**:
  - 대규모 지도 뷰(`SubwayStationMap`), 무거운 일정 뷰(`BusanItinerariesView`) 등 초기 로딩에 즉시 필요하지 않은 화면은 `lazyWithRetry`를 활용해 동적 로딩합니다.

---

## 3. 에러 핸들링 및 복원력 (Resilience)
- **우아한 폴백 (Graceful Degradation)**:
  - 외부 공공데이터 API, 지하철 실시간 정보, Gemini API 등이 다운되더라도 서비스 전체가 크래시되지 않도록 `try-catch`와 로컬 폴백 데이터(`src/data.ts`)를 항상 준비합니다.
- **사용자 친화적 피드백**:
  - 네트워크 오류나 데이터 부재 시 백지 화면 대신 빈 상태(Empty State) 안내 문구 및 재시도 버튼을 제공합니다.
  - 치명적인 렌더링 에러는 최상위 `ErrorBoundary`에서 안전하게 포착합니다.

---

## 4. 가독성 및 문서화 무결성
- **기존 주석 및 라이선스 보존**:
  - 코드 변경 시 관련 없는 기존 주석, JSDoc, 비즈니스 로직 설명, 라이선스 헤더를 훼손하지 않고 그대로 유지합니다.
- **명확한 네이밍**:
  - 함수명은 동작이 드러나는 동사형(`handleSelectStation`, `getLineTheme`), 불리언 변수는 `is-`, `has-` 접두사로 명명합니다.
